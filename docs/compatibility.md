## 已知问题：Codex 应用切回提示

用户在当前发布构建上反馈 Alt+Tab 切回没有提示，Shift 切换正常。复测任务要求 10 次应用往返和 20 次 Shift，但反馈未提供逐次结果，不能记为完成这些次数或据此计算成功率。

对应诊断时段能看到前台身份变化、已知状态、短暂 Unknown 和绘制请求；部分查询未取得光标而回退右上角。`frame visible=true` 仅表示窗口可见标志，不能推翻用户反馈或证明实际显示正确。最终根因待定位，当前未声明修复。排查步骤见 [排障指南](troubleshooting.md)。

## 检测与定位策略

微信输入法的开放状态用于判断中英文，不按 Shift 次数推算。其转换模式在某些 TSF 应用中会保持零，因此不用于覆盖开放状态。

定位依次尝试 Win32 光标、MSAA 光标和 UI Automation。Windows Terminal 对零长度文本范围返回空坐标，程序仅在 Terminal 窗口中对克隆范围扩展到字符单元并校验起点，不读取正文或改变选区。依据：[Microsoft Terminal 范围实现](https://github.com/microsoft/terminal/blob/main/src/types/UiaTextRangeBase.cpp)。

无法定位时回退到当前窗口右上角；这不代表光标定位成功。无法读取状态时不新建提示。已有提示对同一焦点的读取中断最多保留 200 毫秒，之后隐藏。

## 性能与尚未完成的验收

目标为 5 分钟空闲平均 CPU ≤ 0.2%（整机口径）、主辅进程合计私有内存 ≤ 60 MiB、切换到可见提示 P95 ≤ 150 ms。

2026-10-10 对 v0.1.0 发布二进制进行 300.061 秒后台运行采样：记录到整机 CPU 0.041398%、合计私有内存采样峰值 8.50 MiB。期间检测到 7 个 UIA 辅助进程退出，CPU 统计可能不完整，脚本判定 **FAIL（测量无效，不能据此判定达标）**。期间包含人工切换操作，且运行实例启用了诊断日志，也不构成默认配置下的严格空闲测试。辅助进程退出原因仍待进一步区分；不能直接认定为崩溃或某个 API 超时。
