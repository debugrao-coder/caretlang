- 29 项测试通过，覆盖状态去重、首次聚焦、未知状态、过期结果、坐标边界、DPI、透明度、Alt+Tab 显示计时、窗口归属与定位协议。

- UIA 子进程经过启动、无效请求、stdin 关闭、父进程结束和超时隔离检查。

## 检测与定位策略

微信输入法的开放状态用于判断中英文，不按 Shift 次数推算。其转换模式在某些 TSF 应用中会保持零，因此不用于覆盖开放状态。

定位依次尝试 Win32 光标、MSAA 光标和 UI Automation。Windows Terminal 对零长度文本范围返回空坐标，程序仅在 Terminal 窗口中对克隆范围扩展到字符单元并校验起点，不读取正文或改变选区。依据：[Microsoft Terminal 范围实现](https://github.com/microsoft/terminal/blob/main/src/types/UiaTextRangeBase.cpp)。

无法定位时回退到当前窗口右上角；这不代表光标定位成功。无法读取状态时不新建提示。已有提示对同一焦点的读取中断最多保留 200 毫秒，之后隐藏。

## 性能与尚未完成的验收

目标为 5 分钟空闲平均 CPU ≤ 0.2%（整机口径）、主辅进程合计私有内存 ≤ 60 MiB、切换到可见提示 P95 ≤ 150 ms。

早期构建在一台开发机上测得空闲 CPU 0.019789%、私有内存采样峰值约 5.42 MiB。该构建早于后续兼容性修复，**不能作为当前发布版本达标证明**。可通过 `scripts/Measure-Idle.ps1` 重新测量。

当前版本尚未完成每类应用 100 次切换、多屏与实际 100%／150%／200% 缩放、休眠恢复、纯净系统和端到端延迟验收。定位等待最多 180 ms，回退场景可能超出延迟目标。

管理员窗口、安全桌面、远程桌面和游戏不在首版保证范围。微信输入法或目标应用升级后需重新验证。
