# 排障与验证指南

- 生命周期：持续维护。
- 适用范围：Windows 11 x64、微信输入法、CaretLang v0.1.0；其他输入法不据此推断兼容。
- `authority`: 本仓源码、自动测试、发布资产和 [兼容性实测记录](compatibility.md)。
- `last_verified`: 2026-10-10。输入法、Windows 或宿主应用升级后需重新验证。
- `sensitivity`: public；本机日志、截图和用户输入不属于公开文档附件。
- `supersedes`: none。本文补充 README，不替代兼容性结论。

## 先区分四层证据

| 层次 | 能证明什么 | 不能证明什么 |
| --- | --- | --- |
| 自动测试与构建 | 状态、计时、坐标等已覆盖规则正确，程序可构建 | 特定应用实际可用 |
| 状态读取 | 当前焦点确实返回中／英状态 | 定位正确或提示可见 |
| 光标定位与绘制日志 | 得到了坐标，并请求显示浮层 | 用户看到的位置正确、切换过程中没有遮挡 |
| 实际窗口验证 | 该版本、该输入框中提示可见且位置正确 | 所有应用、所有 DPI 或长期稳定性 |

先确认复现动作：Shift 切换输入法、鼠标切换、Alt+Tab 切换应用和应用内部标签切换是不同场景。不要仅凭“Tab 切换”选择修复路径。

## 复现前准备

1. 从托盘退出旧程序，只保留一个实例。确认所用可执行文件与待验收发布包一致，并记录 SHA-256。
2. 使用微信输入法，在普通权限应用的空输入框测试。不要输入真实密码或发送测试消息。
3. 记录 Windows、输入法与宿主版本、DPI、操作顺序及是否使用管理员权限。只保留必要环境信息。
4. 临时启用诊断后再复现；日志目录先自行创建：

```powershell
New-Item -ItemType Directory -Force ./artifacts | Out-Null
./caretlang.exe --diagnostic ./artifacts/runtime.log
```

诊断选项不会控制已有实例；旧实例必须先退出。排障结束后退出诊断实例，以不带参数的方式重新启动。不要直接公开完整日志或聊天窗口截图。

## 状态不显示

先看实际输入法状态是否变化，再检查 `observed`、`switch`、`frame` 和 `render_error`。

- 没有确定状态：检查权限和查询超时。普通权限进程不能可靠读取管理员窗口，不要把拒绝访问解释成输入法不兼容，也不要自动提权。
- 状态变化但没有 `switch`：检查当前窗口和焦点身份、暂停状态以及状态去重。
- 有 `switch` 但没有可见 `frame`：检查后续焦点变化、读取中断、绘制错误，以及 Alt 是否仍按住。
- `frame visible=true` 仍看不到：检查位置、遮挡与显示时长；这一日志本身不是视觉验收。

微信输入法在部分 TSF 宿主中，转换模式会恒为零，而开放状态仍在 0／1 间切换。本版使用后者；不按 Shift 次数猜中英文，也不把此规则推广到其他输入法。

代码入口：[状态读取](../src/platform.rs)、[状态去重](../src/core.rs)、[主循环与诊断](../src/main.rs)。

## 提示固定在窗口右上角

这是光标定位失败的回退位置，状态检测正常不代表定位正常。

1. 原生光标存在时，检查 Win32 光标矩形及屏幕坐标转换。
2. 原生光标缺失时，在辅助进程中依次尝试 MSAA 与 UI Automation；MSAA 不依赖 UIA 查询先成功。
3. 浏览器渲染进程可能与主窗口不同，验证 HWND 层级归属，不强制要求进程 ID 相同。
4. 拒绝把整个输入框矩形当成光标。坐标还必须对应当前前台、焦点与查询代次；旧回复不能用于新窗口。
5. Windows Terminal 的零长度范围可能返回空矩形。只对已识别的 Terminal 窗口克隆范围、扩展字符单元并校验起点，不调用 GetText 或 Select。

如果应用不暴露有效光标，继续标记“定位回退”，不要用鼠标位置或输入框边缘冒充真实插入点。

代码与测试入口：[辅助定位、协议和几何检查](../src/uia.rs)、[屏幕边界与 DPI 测试](../tests/core_tests.rs)。

## Alt+Tab 切回后漏提示

应用激活、输入框恢复焦点、输入法可查询、辅助定位完成不一定同时发生。

- 前台事件重新触发提示；切换期间不接受“新窗口＋旧应用焦点”的混合身份。
- 窗口查询暂时失败后重新准备首次提示，避免恢复到同一状态时被去重。
- 同一焦点已有状态的短中断最多容忍 200 ms，持续未知则隐藏。
- Alt 仍按住时不消耗定位重试或可见时长；松开后再定位和显示。
- 定位等待与显示计时分离。最多等待 180 ms，0.8 秒提示时长从开始显示计时。

这些实现规则已覆盖部分单元测试，但 2026-10-10 用户复测仍反馈 Codex 在 Alt+Tab 切回时没有提示，Shift 正常。该场景验收未通过，不应仅凭单元测试或绘制日志宣布修复。下一次定位需关联前台事件、状态读取失败、光标回复、显示位置和真实可见时刻，区分定位回退与显示时机或遮挡问题。源码入口：[主循环、Popup 与 window_tests](../src/main.rs)。

## 连续切换验收

对每个宿主、输入框和操作类别分别记录，不能混成一个通过率。使用空输入框，切换间隔约 1 秒；每类应用完成至少 100 次后才标注完整连续切换验收。

| 字段 | 记录方式 |
| --- | --- |
| 构建 | 发布标签、源码提交、可执行文件 SHA-256 |
| 场景 | 应用及版本、输入框类型、DPI、权限 |
| 操作 | Shift／鼠标／Alt+Tab，操作次数 |
| 结果 | 正确次数、漏报、误报、位置回退、被遮挡 |
| 时延 | 从真实切换到首个可见提示；P95 需独立记录起点和终点 |

先做 10 次应用切回和 20 次 Shift 烟测以定位缺陷。少量烟测不能写成 100 次验收通过；仅从日志的 `switch` 到 `frame` 计算的时长也不是端到端延迟。

## 性能复测

```powershell
./scripts/Measure-Idle.ps1 -ExePath ./dist/CaretLang/caretlang.exe -Seconds 300 -OutputPath ./artifacts/performance.json
```

脚本统计准确路径对应主辅进程的 CPU 与私有内存。整机 CPU 与单核口径不同；私有内存也不是工作集。进程退出会令这次测量无效，应查明是否发生辅助进程重启。

脚本不强制用户空闲。有人持续操作时，只能报告“后台运行测量”，不能宣称完成严格空闲验收。采样峰值也可能遗漏小于采样间隔的瞬时峰值。必须核对测量二进制的哈希，不能用旧构建数字证明当前发布版本达标。
